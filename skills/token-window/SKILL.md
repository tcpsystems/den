# Token window

This is an optimisation suggestion for production work. It is not a restriction. An orchestrator may still start a seat with a long packet.

Agents tend to stay sharper when the whole input is under about 32,000 tokens. Focus slips as one chat runs on and on. Split the brunt of coding, review, and research across fresh fast seats instead of one long thread.

The 32,000 tokens include everything attached to the seat: identity, soul, persona, skills, rules, and the task. Count those before the task text. If the attachments already fill the window, drop optional parameters. Do not drop a safety limit to make room.

The orchestrator may pass many parameters. Only the packet fields that the step needs are required. The rest are optional.

A fast seat does one chunk and stops. The orchestrator keeps the long memory. The seat does not.
