# Mesh kb put and kb query

Draft. One key per section. A later section supersedes. Nothing is deleted.

Source opened: `plan.md`, Memory rules through Seat expansion. Followed: `research/verified-lines.md` (next fetch carries a pointer only; steer, ledger body, and Rail stay out) and `research/topics.md` (append a row or store a later section; do not edit the current one). Rail stays empty. Superpowers' human-approval wait is not this store rule.

## Contract

`KbKey` is one section id. `kb_put` appends one `SectionRecord` under that key. `kb_query` returns the latest record for one key, or the ordered history when history is requested. A put never replaces bytes in place. Current knowledge changes only when a later record is appended. Foxcore is that latest record, not a second store.

The seven fields are the only record fields: Section, Function, Read, Do, Write, Next, Rail. Write is this one mesh kb key. Rail is stored as empty. The next fetch may carry a pointer to a side record. It does not carry the steer line, the ledger body, or the Rail switch.

## Types

- `KbKey`: one section id. It is the sole key for that section.
- `SectionRecord`: Section, Function, Read, Do, Write, Next, Rail. No eighth field.
- `KbPut`: key plus one new record. It is an append.
- `KbQuery`: one key, plus a flag for latest or history.
- `KbHit`: the latest record, or the append-ordered history. Absent key returns no hit.

## Functions

- `kb_put(KbPut) -> KbKey`: append the record under its one key. Refuse a second key, an in-place edit, or a delete.
- `kb_query(KbQuery) -> KbHit`: read the latest record, or the history in append order. Read-only.
- `current(KbKey) -> SectionRecord`: the last appended record for that key. A later section supersedes by append, not by overwrite.
- `next_fetch(KbKey) -> SectionRecord`: the current record with Rail empty and no steer line or ledger body. A side-record pointer is the only extra.

## Invariants

- One section has one kb key. A put for another key is a different section.
- A later append supersedes earlier records for that key. Earlier records remain.
- No delete, no in-place rewrite, and no truncation of history.
- A record has the seven fields and no others. Rail on the stored section and on the next fetch is empty.
- The mesh stores and fetches. It does not choose a model.
- A lead may cut Next. The mesh appends that cut on the progress record. The lead writes no corpus and no kb key.
