# Leaders

Big leaders configure, start, and lead the orchestrators. They do not implement the section and they do not pick a model. The mesh stays the bus.

## Tiers

| Tier | Does | Does not |
| --- | --- | --- |
| Big leader | Sets the orchestrator, names the want, cuts the prompt, surveys the landscape, finds the skill, tiebreaks when a lower tier is not decided | Write the section function, store the corpus, flip Rail |
| Orchestrator or council | Runs one project. Hands each seat its packet. Collects the notes. | Become a second bus or a model router |
| Section seat | One niche, one skill, one function, one check | Decide a line that two notes have not agreed |

A council is a set of orchestrators the big leader started. It is not a vote that replaces the two-note rule.

## What a big leader is for

1. Wants. Write the user's want in the packet before any seat starts. If the want is missing, the leader stops and asks. A seat does not invent it.
2. Prompts. Cut each seat prompt to the section, one skill body, and the tools that section named.
3. Deep plan. The plan is `plan/PLAN.md` plus the niche note. The leader reads both before starting an orchestrator.
4. Landscape. Name the current repos and tools that already exist. den, radar, fox, foxd, floki, the local embedder, smolvm.
5. Skills. Look for one skill whose description matches. `skills/select-skill` returns that one path.
6. Tiebreak. Only when the lower tier is not decided. The leader applies that one skill to the research note. The note already holds the sources. The leader does not add sources in the same pass.

## Evidence, then user context

A research note is presented with no slant. Each claim has a URL. Conflicting claims stay side by side. The leader does not bury one to favor the other.

After that page is complete, a separate block labeled `User context` applies what is already known about this user. That block is the bias, and it is named. It does not rewrite the evidence. It says which option fits the want, and why, from context the leader was given.

If the context does not decide, the leader says so. The lower tier stays undecided.

## Start an orchestrator

The leader writes one packet:

- Section: the project
- Function: the orchestrator's job
- Read: the plan path and the niche note
- Do: the seats to start, each with one skill
- Write: where their notes go
- Next: the seat that reviews
- Rail: empty unless the human flipped it

Then the orchestrator runs. The leader does not sit inside the tool loop.
