# SDK lessons

These are expansions of rules already in the foundation. They are not a rewrite.

| Source | Keep | Leave out |
| --- | --- | --- |
| Vercel AI SDK | A fixed tool order | The 20-step loop, and a tool list stuffed into the environment |
| Cloudflare Agents | One alarm that calls a named method | Durable Object SQL, and a heap that dies on sleep |
| Hermes | Flush the note before the summary | Extra memory products, and a process-global working directory |
| OpenCode | A read-only child | Permission keys as a second policy |
| Reasonix | A stable prefix, then the packet | Trace export |
| OpenAI Agents | Jail state the model never sees | A handoff that copies the parent thread, and default trace upload |
| AgentScope | The worker's final reply | Running arguments that were repaired after a length stop |
| LangGraph | Save the argv result after the call returns | Resuming inside the same writer |
| Goose | One skill by description | Memory extensions and code mode |
| Pydantic AI | Validate the argv call before it runs | Handing a jail failure back to the model for a retry |

The harness stays dynamic because the plan is text, the tool is argv, and the skill is a file. It does not add an AST executor, a Wasm runtime, or an agent bus that copies parent state.
