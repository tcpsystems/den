# Structures we may use

den may use a structure from LangChain, LangGraph, Deep Agents, or OpenViking when the packet names it. Using a structure does not move the seat into that runtime. The mesh stays the bus. The model id stays the one in the packet.

| Source | Structure we may take | What it does not become |
| --- | --- | --- |
| LangChain | A tool definition and a model client | The seat loop |
| LangGraph | A checkpoint of a finished section. A human pause before a write. | The way the next seat is chosen. The live store. |
| Deep Agents | Load one skill when the description matches. A subagent is a child packet. | A shell the model is trusted with. A filesystem that replaces smolvm. |
| OpenViking | `viking://` resources and memories. A later note supersedes. Nothing is deleted. | A second brain, or the read path for fast memory |

## Deep research

A deep research note is evidence first. Each claim has a URL. Conflicts stay side by side. The crutch that writes it is the deep-dive seat. The big leader adds `User context` only after that page is done, and labels it.

## OpenViking

Fast and recent stay on disk. OpenViking at `127.0.0.1:1933` keeps the long note. The OmniRoute docs condensation is `viking://resources/omniroute/omniroute.xml`. Embeddings for that store come from `127.0.0.1:8091`. A seat does not embed through OmniRoute.

## Rule

If the packet does not name the structure, do not import it. One skill, one structure, one check.
