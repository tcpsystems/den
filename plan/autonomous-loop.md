# Autonomous loop

This is the operating plan. A hint can change a task. It does not change this loop.

## Own

Den owns the packet, grant, skill choice, tool result, evidence, and memory. `dentui` shows the work. `denctl` controls it. OmniRoute supplies the model. MCP supplies tools. A2A reaches an external agent. Akash supplies rented GPU capacity only after a local model route is saturated.

## Refuse

Do not add another coding CLI as the kernel. Do not deploy to Akash without an explicit deployment task. Do not load ten skill bodies. Do not let a model hold a credential.

## Loop

1. Observe the queue, failures, cost, and latency.
2. Read ten skill names. Accept one or deny all.
3. Run one tool call inside the granted boundary.
4. Record the result and whether its check passed.
5. Compact the volatile context. Keep the stable prefix.
6. Promote a change only after its check passes twice.
7. Stop on a denied grant, missing evidence, or budget breach.

## Workers

Readers extract from local clones. Reviewers challenge one claim. Builders write one function and its failing test. The orchestrator accepts one result. Text-only seats do not count as workers.

High concurrency is required. Independent tasks run together. One worker owns one task. The cap is the smallest limit among CPU, memory, provider quota, and the task budget. OmniRoute stays the model gateway. Den does not rebuild it.

Quality outranks speed. A factual claim needs a path, command output, or source URL. Unverified text is marked unknown. Two reviewers check a production change. Git uses one branch and one commit per change. History is reverted by a new commit, not rewritten. A mixed diff is split before commit. Nothing is pushed before its check passes.

Agents may create provider accounts and accept their terms. Credentials go only to Vaultwarden at `https://vault.tcp.systems`. A model prompt, log, commit, or report never contains a secret. The DeepSeek balance stays unused unless a task names it.

A long-lived machine uses one base image plus an ordered change log. Each change records its parent, command or diff, result, and restore check. Rebuild from the base and the log. Do not make another full copy unless the log cannot replay. Before a worker edits a dirty branch, it records the branch and `git status --short` in the evidence. A change that cannot name its restore point stops.

## See

`densee` opens one local page in a headless browser. It captures desktop and mobile screenshots, console errors, and the DOM outline. It writes those under the run evidence. It does not change the page. A visual difference becomes one design task. The task passes only when the next capture no longer shows that difference.

Files, plugins, and skills use the same catalog shape: id, version, source, grant, and check. A file manager lists artifacts. A plugin adds catalog rows. A skill is injected only after it is accepted. No manager gets its own daemon.

## Surfaces

`denctl` serves the local board. A runner opens that page at 1440, 768, and 390 pixel widths, takes one screenshot at each width, and writes the path and a measured fault. A fault is overflow, overlap, unreachable action, or unreadable text. The next task fixes one fault and takes the same three screenshots again.

The same board is the file view, plugin view, and skill view. A file row shows path, owner, and state. A plugin row adds catalog entries and nothing else. A skill row shows the ten names and the one accepted body.

## Exploration

A research task reads one repository or page, records the source, and returns one useful mechanism. Skill development writes one skill only after the same source appears in two notes. No task browses the whole catalog.

## Consensus

Three long-context workers review one proposal. Each returns agree, change, or reject. A change names one line. The proposal passes when two agree and no reject remains. Otherwise it stays research.

## Cost

The stable prefix is cached. A worker receives names, scores, and paths, not full skill bodies or catalogs. A repeated result is rejected before another model call. The route order is local, cached, then paid. A paid call has a token and money cap in the task.

## Coverage

A surface enters coverage only when it has an owner, a source, and a check. The first groups are Den runtime, local Linux security, virtualization, design, and external platforms. Security work is defensive: updates, permissions, firewall, SSH policy, pinned images, and tests. Attack or intrusion work is refused. Git records every accepted change. A backup is named before a destructive change.

## Knowledge

`mcp/catalog.json` is the provider list. Discovery appends one proposed row. A grant starts it. `inject.One` loads one accepted skill. A new skill needs two agreeing notes and a passing check. OpenViking stores the ledger. The local 4096-dimension embedder is shared. Brand, market, design, and project strategy are separate plans.

## Plan

A plan has one owner, one ordered sequence, one budget, and one check. Text without those four fields is research. A discussion becomes a plan only when one worker writes those fields. The first plan is Den. The first onboarded project is radar, read only. Foxcore follows as ideology, skills, fox, foxd, then floki. OmniRoute, Cloudflare, and Stripe need separate plans. SEO, crawling, parsing, and proxy validation need separate plans too.

## Expansion

A new provider, model, or project is a catalog row. The packet and role names stay fixed. A project gets one branch, one owner, and one evidence record. A worker improves one measured fault. A worker that repeats a finished result stops. Deep research and onboarding are tasks. They return sources and a proposed catalog row. They do not widen the loop.
