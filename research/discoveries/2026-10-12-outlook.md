# Outlook

## Missing information

- `plan/needs.md` says `develop` "has no section implementation" and that the twenty-three `r*` branches are drafts with several seats returning "a placeholder" or stopping on "a 401 from the OmniRoute route," but it does not say which branches hit the 401 or how that credential problem was resolved.
- `README.md` points to `plan/PLAN.md` as "the plan," but that exact path was not among the files read for this note, so it is unclear whether `plan/PLAN.md` and `plan/BASE.md` cover the same ground or different ground.

## Needs clarification

- `plan/needs.md` says a controller is "a later binary" with no date or trigger condition named for when "later" becomes "now."
- `plan/analysis/skill-adoption.md` is dated 2026-10-12 and calls itself "a suggestion until two notes agree and a page read confirms the licence and the file shape," but does not say who writes the second note or where that agreement is recorded.

## Needs more detail

- `plan/BASE.md` names the embedder host-boundary rule ("If it is down, the seat waits") but does not describe what a seat does while it waits — no retry count or timeout is given in the lines read.
- `plan/needs.md` requirement 6 says draft `r*` commits "stay on their branches until a check seat reads them and a second note agrees," but does not define what the check seat checks for or where that first note is filed.
- `README.md` lists what a seat "already has" (model id, fast/recent memory, embeddings, a smolvm guest, one route skill) but does not describe how those five things are wired together at seat start time.

## Creative risks

- `plan/analysis/skill-adoption.md` invites adoption from many named outside sources (ECC, Picrew, void-agent, Anthropic plugins, figma, cisco-ai-defense, ai-boost) in a single matrix; treating any one "Keep" column entry as already adopted before "two notes agree" would contradict the file's own caveat.
- `plan/horizon.md` lists "Structure-aware" use of LangChain, LangGraph, Deep Agents, or OpenViking "when the packet names it," which creates a risk that a packet author imports a structure's assumptions (e.g. a graph scheduler) in a way that quietly becomes the bus, which the same row says must not happen.

## What could go wrong

- `plan/BASE.md`'s packet rule that "a child packet does not carry the parent's Write or Rail" is a strict handoff contract; `plan/needs.md` separately describes a draft "child handoff" subject still only on an unmerged `r*` branch, so the enforced rule and the drafted implementation could drift apart before they are reconciled.
- `plan/needs.md` warns that several `r*` branches "stopped on a 401 from the OmniRoute route," which shows a credential or scope failure already reached draft seats; if that same gap reaches a live packet run under `plan/omniroute.md`, a seat could stall mid-task the same way.

This file is research. It does not change plan/BASE.md.
