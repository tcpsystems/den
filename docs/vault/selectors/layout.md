# Selector memory

A selector is how a seat picks a tool, a niche, a skill, or another named row. The memory of a selector is the row that worked, not a second catalog.

| Selector | Remember | Do not remember |
| --- | --- | --- |
| tool | The tool name, the argv, pass or fail | The tool catalog |
| niche | The niche id and the one skill it loaded | The niche map |
| skill | The skill path and pass or fail | The skill body, twice |
| model | The model id the packet named | A router policy |
| section | The section id and the function | The parent packet |

A repeated task hits when the function line, the read paths, and the skill path match exactly. That hit reads the file. It does not embed again.

A selector note is backed up with the rest of the tree. Rebuilding the files rebuilds the selector memory. Vectors are derived and can be embedded again from those files.
